01

Arquitetura geral

três camadas, dois sensores, um filtro
MÓDULO 1

Visão · Fluxo Óptico

A cada quadro, uma grade de blocos é comparada com o quadro anterior por correspondência de blocos (block-matching), estimando o deslocamento médio de pixels — a base para a rotação em yaw.

MÓDULO 2

Inercial · Acelerômetro

O vetor de gravidade lido do DeviceMotionEvent define roll e pitch absolutos por trigonometria — mas é cego ao giro no eixo vertical (yaw).

MÓDULO 3

Fusão · Filtro Complementar

Combina a resposta rápida da câmera com a estabilidade do acelerômetro num único ângulo de saída, renderizado ao vivo no gimbal 3D.

02

O processo matemático

o que o console está calculando agora

A · Velocidade angular visual

O deslocamento médio dos blocos rastreados entre dois quadros, dividido pelo intervalo de tempo, aproxima a velocidade angular no eixo Z:

ω = Δθ / Δt  ·  K

Onde K é o fator de calibração ajustável no painel — compensa o campo de visão e a distância focal da sua câmera.

B · Roll e pitch por gravidade

Com o vetor de aceleração (Ax, Ay, Az) da IMU, os ângulos de inclinação vêm direto da trigonometria do vetor gravidade:

pitch = atan2(Ay, √(Ax² + Az²))
roll  = atan2(−Ax, Az)

C · Filtro complementar

Cada ângulo final pondera a integração rápida da câmera contra a leitura absoluta e estável do acelerômetro:

ângulo = α·(ângulo + ω·Δt) + (1−α)·ânguloacc

No console acima, α é o slider "Confiança na câmera" — perto de 1 confia quase tudo na câmera; valores menores puxam mais para o acelerômetro.

D · O limite físico do yaw

Girar em torno do eixo vertical não altera a direção da gravidade — por isso o acelerômetro nunca contribui para o yaw. Nesta demo, o yaw vem só da câmera e é congelado quando a imagem perde textura rastreável.

03

Referência: pipeline em Python (OpenCV)

a versão desktop, com câmera dedicada
gyro_emulator.pyLucas-Kanade · Shi-Tomasi
import cv2
import numpy as np
import time

cap = cv2.VideoCapture(0)
lk_params = dict(winSize=(15, 15), maxLevel=2,
    criteria=(cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 10, 0.03))
feature_params = dict(maxCorners=100, qualityLevel=0.3, minDistance=7, blockSize=7)

ret, old_frame = cap.read()
old_gray = cv2.cvtColor(old_frame, cv2.COLOR_BGR2GRAY)
p0 = cv2.goodFeaturesToTrack(old_gray, mask=None, **feature_params)
last_time = time.time()

while True:
    ret, frame = cap.read()
    if not ret: break
    now = time.time(); dt = now - last_time; last_time = now
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    if p0 is None or len(p0) < 10:
        p0 = cv2.goodFeaturesToTrack(old_gray, mask=None, **feature_params)

    if p0 is not None:
        p1, st, err = cv2.calcOpticalFlowPyrLK(old_gray, gray, p0, None, **lk_params)
        good_new, good_old = p1[st == 1], p0[st == 1]
        dx = np.mean([n[0] - o[0] for n, o in zip(good_new, good_old)])

        K_calib = 0.5  # ajuste conforme a lente
        gyro_z = (dx / dt) * K_calib  # graus / segundo

        # fusão opcional com acelerômetro via serial/I2C:
        # gyro_z = alpha*(gyro_z) + (1-alpha)*acc_yaw_ref

        p0 = good_new.reshape(-1, 1, 2)

    old_gray = gray.copy()
    if cv2.waitKey(1) & 0xFF == ord('q'): break

cap.release()

O console acima implementa a mesma ideia inteiramente em JavaScript (block-matching em vez de Lucas-Kanade, para rodar sem dependências binárias no navegador), acoplado ao DeviceMotionEvent no lugar de uma IMU física via serial.

Desafios de engenharia

e como este console lida com cada um
ProblemaDescriçãoMitigação aplicada
LatênciaCâmeras rodam a ~30–60 Hz; giroscópios reais chegam a 1000 Hz.Integração contínua entre quadros + suavização exponencial no gimbal.
Motion blurMovimentos rápidos borram a imagem e quebram o rastreamento.Filtro complementar reduz automaticamente o peso da câmera quando a variância do fluxo dispara.
Falta de texturaSuperfícies lisas (paredes brancas) não dão pontos para rastrear.Detector de variância de textura congela o yaw e acende o LED de aviso no painel.
Distorção de lenteLentes grande-angulares deformam o deslocamento nas bordas.Fora do escopo desta demo — recomenda-se calibração com cv2.calibrateCamera na versão desktop.
Roll (rotação no eixo óptico)Fluxo óptico translacional simples não separa rotação-no-plano de deslocamento lateral.Roll é estimado majoritariamente pelo acelerômetro nesta demo; fluxo afim/rotacional fica como próximo passo.
